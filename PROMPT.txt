The orb system has already been refactored and now includes an effect manager or similar modular orb architecture. That refactor is acceptable. This task is NOT to do more large architecture work. This task is to use the current orb framework to implement actual new playable orb content.

Main objective:
Implement a first real content pack of new orb types on top of the existing orb/effect system.

Important constraints:
- Do not spend the effort on more broad refactoring unless a very small change is required to support these orbs.
- Preserve the current core gameplay feel.
- Keep the player bouncing mechanic unchanged.
- Keep diffs focused and practical.
- Prefer typed GDScript.
- Validate all work with ./devscripts/test.sh and do not finish unless it exits 0.
- Add or update GUT tests for deterministic logic related to orb effects, effect duration, stacking/conflict behavior, and score changes.

Implement these orb types:
1. Burst Orb
   - When collected, it clears nearby collectible orbs in a radius.
   - Cleared nearby orbs should count as collected/cashed in for the player.
   - Should use current orb/effect/spawn systems cleanly.

2. Vertical Line Orb
   - When collected, it clears collectible orbs in a vertical line through its position.
   - Cleared orbs should be cashed in for the player.

3. Horizontal Line Orb
   - When collected, it clears collectible orbs in a horizontal line through its position.
   - Cleared orbs should be cashed in for the player.

4. Slow Fall Orb
   - Temporarily reduces the ball’s falling speed / gravity effect in a controlled and readable way.
   - Duration should be configurable.
   - Must integrate with the current effect manager instead of using hardcoded one-off logic if possible.

5. Sticky Head Orb
   - Temporarily makes the ball “stick” very briefly to the player’s head before bouncing away.
   - This should improve control slightly without breaking the core bounce mechanic.
   - Duration and/or stick time should be configurable.

6. Double Value Orb
   - Temporarily increases score gained from orb pickups and/or score events, depending on the current scoring architecture.
   - Duration should be configurable.

7. Combo Starter Orb
   - Starts or boosts a combo/multiplier window if the current architecture supports it.
   - If combo infrastructure does not yet exist in a reusable way, implement the smallest practical version needed for this orb only if it can be done safely and testably.
   - Do not overbuild a huge combo system.

8. Drifter Orb
   - A moving orb that drifts in a simple readable pattern.
   - Its movement should be configurable and should not require major new architecture.
   - It should still be collectible through normal gameplay.

Implementation guidance:
- Use the current orb/effect manager and newly refactored architecture as the base.
- Prefer data/config-driven definitions where possible, but do not over-engineer.
- Make each orb type clearly identifiable in code and easy to extend later.
- Reuse shared orb logic instead of duplicating behavior.
- Keep moving orb behavior simple and stable.
- Keep chain-reaction collection logic deterministic where possible.

Testing expectations:
Add or update tests for:
- Burst radius collection logic
- Vertical and horizontal line clear logic
- Effect application/removal for timed effects
- Score multiplier or double value logic
- Sticky head / slow fall logic where deterministic pieces can be isolated
- Drifter orb behavior logic if there is a deterministic movement component that can be unit tested

Manual verification expectations:
In your final summary, include clear manual verification steps for each implemented orb so I can quickly test them in-game.

Definition of done:
- All 8 orb types are implemented in the game codebase
- They are integrated into spawning/content definitions so they can actually appear or be tested in-game
- ./devscripts/test.sh exits 0
- Existing gameplay is not unintentionally broken
- Final summary includes:
  1. which files were added/changed
  2. which tests were added
  3. how each orb behaves
  4. exact manual steps to verify each orb in-game
